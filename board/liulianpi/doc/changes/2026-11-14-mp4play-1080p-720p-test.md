# 变更记录 2026-11-14：mp4play 分辨率上限、buffer 策略与主机转码

- 日期：2026-11-14
- 主题：确认 F1C100s 的实时解码上限为 720p，固定 1024x600 日常格式，增加主机转码脚本
- 相关改动：
  - `package/vdec-selftest/src/mp4play.c`
  - `tools/convert-for-f1c100s.sh`
  - `board/allwinner/suniv-f1c100s/linux.defconfig`（CMA 最终保持 16 MiB）

## 背景

原始文件是手机录制的 HEVC 1080p：

```text
codec_name=hevc
codec_tag_string=hvc1
width=1920
height=1080
r_frame_rate=30/1
audio=AAC-LC 48000Hz stereo
duration=157.7s
size=308,524,643 B
rotation=-180
```

F1C100s 的 cedrus/VE 只支持 H.264，不支持 HEVC，原文件无法直接播放。
另外 `/mnt/VMShare/VMShare/...` 是主机路径，目标机必须放到 SD 卡上，通过
`/mnt/sd/...` 访问。

## 转码产物

主机侧用 ffmpeg 转成 H.264 Baseline + AAC：

| 文件 | 分辨率 | Profile/Level | 大小 |
| --- | --- | --- | --- |
| `VID_20261102_223149_f1c100s.mp4` | 1024x600 | Constrained Baseline 3.1 | 33,410,577 B |
| `VID_20261102_223149_720p.mp4` | 1280x720 | Constrained Baseline 3.1 | 46,080,934 B |
| `VID_20261102_223149_1080p.mp4` | 1920x1080 | Constrained Baseline 4.0 | 93,727,155 B |

共同参数：

```text
30fps，yuv420p，无 B 帧，GOP 30，AAC-LC 48kHz stereo
```

主机侧 `vdec_selftest_host -H` 对 1080p/720p 都解析出 4732 帧，POC 显示顺序正常，
没有多 slice 警告。

## 实测结论

### 16 MiB CMA

- `720p -b 4` / `-b 5`：正常打开、解码、显示，约 30fps
- `1080p -b 4` / `-b 5`：在第一个 `3,133,440 B` buffer 上
  `cma_alloc: alloc failed`，16 MiB CMA 没有连续的 3 MiB 块
- `1024x600`：正常播放

### 32 MiB CMA（仅测试）

- `1080p -b 4` 可以过 CMA、打开 capture 并出图
- 但每帧 `wait` 约 **55~88ms**，对应约 **11~18fps**
- 30fps 需要 33ms/帧，VE 吞吐不够
- `720p` 默认 7 和 `-b 4` 都是约 30fps

结论：

> **720p 是 F1C100s 的实时解码上限。1080p 能解，但只有 11~18fps，不能实时播放。**

因此 1080p 不作为支持格式，32 MiB CMA 也没有日常收益，最终回到 16 MiB。

## 最终策略

### 1. CMA 保持 16 MiB

```text
CONFIG_CMA_SIZE_MBYTES=16
```

普通内存恢复约 36 MiB，为后续自动挂载/播放列表留余量。

### 2. 播放格式

```text
日常：H.264 Baseline / 1024x600 / 30fps / AAC-LC 48kHz
最高：H.264 Baseline / 1280x720 / 30fps / AAC-LC 48kHz
```

屏幕本身是 1024x600，日常用 1024x600 解码负载最低、文件最小。

### 3. mp4play buffer 策略

- 1024x600：自动 6 个 capture buffer
- 大于 1024x600（如 720p）：自动降到 4 个
  - 720p 4 × 1.43 MiB ≈ 5.7 MiB，16 MiB CMA 足够
  - 已实测 720p `-b 4` 约 30fps
- `-b <buffers>` 仍可手动覆盖
- 大于 720p 打印警告：

```text
warning: WxH is above the 720p real-time capability; playback may be slow or fail
```

### 4. 主机转码脚本

新增：

```text
tools/convert-for-f1c100s.sh
```

默认 1024x600：

```sh
./tools/convert-for-f1c100s.sh input.mp4
# 输出 input_f1c100s.mp4
```

可选 720p：

```sh
./tools/convert-for-f1c100s.sh --720p input.mp4
# 输出 input_720p.mp4
```

默认保持比例并补黑边：16:9 的 1080p 源输出成 1024x600 后，画面实际是
1024x576，上下各有 12px 黑边。这是源文件自带的黑边，不是播放器加的。

如果希望画面铺满 1024x600，需要裁掉左右各约 5%：

```sh
./tools/convert-for-f1c100s.sh --fill input.mp4
# 输出 input_f1c100s_fill.mp4，1024x600，无内嵌黑边
```

`--fill` 使用：

```text
scale=1024:600:force_original_aspect_ratio=increase,crop=1024:600,setsar=1
```

`--fill` 可以和 `--720p` 组合。

固定参数：

```text
H.264 Constrained Baseline
30fps
-refs 1 -bf 0 -g 30
AAC-LC 48kHz stereo
+faststart
```

这样输出文件对播放器最友好，也避免高 ref/B 帧带来的 DPB 压力。

## 目标机使用

```sh
mount -t vfat /dev/mmcblk0p1 /mnt/sd

# 日常 1024x600
mp4play /mnt/sd/input_f1c100s.mp4

# 720p，自动 4 buffers
mp4play /mnt/sd/input_720p.mp4

# 手动覆盖 buffer 数
mp4play -b 5 /mnt/sd/input_720p.mp4

# 1080p 仅能力验证，会警告且可能很慢
mp4play -b 4 /mnt/sd/input_1080p.mp4
```

## 已知限制

- 只支持 H.264 视频 + AAC 音频；HEVC/VP9/AV1 需要主机转码
- 1080p 能解但 11~18fps，不实时，A/V 会逐渐不同步
- 720p 是实时上限；更大分辨率不建议
- 720p 的 4-buffer 自动策略针对 baseline/no-B-frame；高 ref/B 帧素材可手动 `-b`
- 1920x1080 已验证仅能慢速解码；其他非标准分辨率未验证
